## Initial finding remediated

Slither initially identified a reentrancy surface in `MigrationLockbox.deposit`: a token transfer occurred before the nonce/accounting state was committed.

The remediation:

1. added a reentrancy guard;
2. commits the unique nonce and `totalLocked` accounting before token interaction; and
3. verifies the post-transfer lockbox token balance covers `totalLocked`.

The post-fix Slither scan reported zero findings.

## Properties tested

- only the configured migration Safe can call `mintForDeposit` or `closeMigration`;
- a deposit ID cannot mint twice;
- Base supply cannot exceed the 1B Elysium-origin supply cap;
- lockbox token balance and `totalLocked` accounting agree for ordinary deposits and against the exact 2,186-byte runtime bytecode of live Elysium `$PHNTMOP` (`0x3156C23C07a88Eb91049DfA97106823E8e418BA3`);
- fee-on-transfer tokens, false-returning tokens, and reentrant token callbacks are rejected atomically;
- 2-of-3 Safe threshold simulation blocks 1-of-3 execution, permits 2-of-3 execution, and enforces permanent one-way closure via `closeMigration()`;
- fuzzed deposit amounts preserve lockbox accounting.

## Live Elysium `$PHNTMOP` bytecode verification

Direct RPC bytecode disassembly of `0x3156C23C07a88Eb91049DfA97106823E8e418BA3` on Elysium (`https://rpc.elysium.kinetiq.xyz`, Chain ID `99901`) confirmed:

- Exact 12 dispatcher selectors: `name()`, `symbol()`, `decimals()`, `totalSupply()`, `balanceOf(address)`, `allowance(address,address)`, `approve(address,uint256)`, `transfer(address,uint256)`, `transferFrom(address,address,uint256)`, `rewardHook()`, `metadataUri()`, and `tokenURI()`.
- Zero proxy or self-destruct opcodes (`DELEGATECALL = 0`, `CALLCODE = 0`, `SELFDESTRUCT = 0`).
- Zero administrative, pause, fee, blacklist, mint, or burn selectors.
- `rewardHook()` is an immutable constant hardcoded to `address(0)` in the runtime bytecode (`0x0136` and `0x053a`), meaning the hook branch is permanently skipped during transfers.

## Residual design risks and required next work

1. **Cross-chain trust:** Base cannot directly validate Elysium events in this design. The 2-of-3 migration Safe is an attestation authority. Public reconciliation and independent signer practice are mandatory. Do not describe this as trustless.
2. **Existing-token behavior:** Elysium `$PHNTMOP` source verification and behavior confirmation remain incomplete because the public explorer rate-limited verification lookups. The lockbox assumes standard `transferFrom` behavior and rejects an insufficient post-transfer balance.
3. **Safe integration:** tests currently model the Safe boundary with the test contract. A real Safe deployment/configuration and end-to-end rehearsal are still required.
4. **Test expansion:** add Elysium/Base fork/rehearsal coverage, adversarial token tests, deployment/verification scripts, and an off-chain reconciliation checker before any external audit.
5. **Independent review:** obtain an external smart-contract review after the above work. Do not deploy or seed Base liquidity before high/critical review findings are remediated.
